LogMerry

Rapport de forge. Objectif : tester si l'idée et le MVP tiennent. Issue : renforcée.

Cockpit personnel de conseil No-Code/IA (mini CRM, factures, échéances) avec un assistant RAG qui cite ses sources, construit pour le Workshop 8.

Décisions verrouillées

  • Une seule base Supabase. Données fictives pendant le WS8, puis purge (embeddings et historique inclus) ; seul le portfolio est conservé.
  • MCP Supabase autorisé tant que la base est fictive ; à débrancher avant la première vraie donnée client.
  • La contrainte est la date (fin de formation le 8 février 2027), pas les 130 h. Capacité déclarée : 35 h/semaine.
  • Jalon du 30 octobre 2026 : RAG de bout en bout. Sinon, aucune nouvelle fonction avant sa correction.
  • Citations vérifiées à deux niveaux : contrôle automatique des identifiants cités à chaque réponse, vérification manuelle sur le jeu de test (réponses présentes, absentes, piège inter-comptes).
  • Chat dans une fonction Supabase ; n8n pour l'asynchrone (ingestion, rappels, résumé hebdomadaire, calendrier).
  • Embeddings : RGPD, puis qualité en français, puis coût. Modèle à choisir avant la première migration.

Écarté, et pourquoi

  • Colonne « fictif » par ligne : mélange démo et réel, risque de fausser la jauge ou de citer une note de démonstration.
  • Second projet Supabase pour le réel : proposé, non retenu.
  • Sacrifier du périmètre pour tenir 130 h : la contrainte réelle est le calendrier.
  • n8n pour le chat : un maillon de plus à sécuriser.

Points faibles restants

  • 35 h/semaine sur environ 17 semaines : déclaré, non vérifié.
  • Le CRM se justifie surtout par le RAG (10 à 20 entités) : risque de dérive de périmètre.
  • Le modèle d'embeddings n'est pas encore choisi.
  • Critères de Richard, nom public, statut juridique et plafond : encore inconnus.
  • L'ingestion asynchrone ajoute n8n à la chaîne avant le jalon du 30 octobre.
