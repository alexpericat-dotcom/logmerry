# Accessibility Review : LogMerry (WCAG 2.1 AA + 2.2 items)

Scope: DESIGN.md, EXPERIENCE.md, .memlog.md, PRD NFR-2. Read-only. Only gaps (missing or contradictory specs).

## Contrast recomputation

Every pair declared in DESIGN.md (Colors, light and dark, and the gradient pairs) was recomputed with the WCAG relative-luminance formula. All declared values match (12,41 / 10,60 / 6,65 / 5,68 / 5,96 / 5,09 / 7,08 / 6,04 / 7,42 / 6,34 / 3,28 ; dark 9,93 / 8,48 / 7,47 / 5,98 / 7,11 / 5,69 / 6,32 / 5,06 ; g1 10,60, g2 7,47, g5 6,65). No declared ratio is wrong. The gaps are pairs that are **not declared** (F-02, F-03, F-04, F-20):

| Ring Sneezeweeds on primary fill Sneezeweeds (dark) | 1,00 | 3 |
| Marker Tobiko on fill Kyuri (light, usage >= 90 %) | 2,03 | 3 |
| Marker Sneezeweeds on fill Sneezeweeds (dark, usage >= 90 %) | 1,00 | 3 |

## Findings

### High

**F-01 High. Language attribute not specified** (EXPERIENCE.md, Foundation / Accessibility Floor; DESIGN.md Typography). Nothing says `<html lang="fr">`. The Supabase/Next.js template ships `lang="en"`; 3.1.1 (A) fails and VoiceOver reads French with an English voice. *Suggested wording (Accessibility Floor):* « `<html lang="fr">` sur toutes les pages, y compris le portfolio public ; tout extrait ou terme en anglais porte `lang="en"`. »

**F-02 High. Focus ring is the same colour as the primary fill** (DESIGN.md, `ring` = `primary`, light #4B5D16 and dark #F2B635; EXPERIENCE.md Interaction Primitives "Focus"). On `button-primary` the ring is invisible (1,00:1). Same for the checked checkbox (border `input` = ring). 2.4.7 and 1.4.11 fail. *Suggested wording (DESIGN.md Colors):* « Anneau de focus : 2 px `{colors.ring}` avec décalage de 2 px sur `{colors.background}` (`ring-offset`), donc 3:1 minimum contre le fond ET contre le contrôle ; ne jamais supprimer `outline` sans équivalent (mode contraste forcé : `outline: 2px solid Highlight`). »

**F-03 High. `accent`, `secondary`, `muted`, `popover` and `card` are the same colour** (DESIGN.md frontmatter: all #ECE2CE light, all #2E4310 dark). shadcn highlights the keyboard-active item of Command (⌘K), DropdownMenu, Select and table-row hover with `bg-accent` on a `bg-popover` surface: the active item is invisible. Same for inactive Tabs, hovered `task-row`/table rows, sidebar current page. 2.4.7 and 1.4.11 fail. *Suggested wording:* « `accent` doit se distinguer de `popover`/`card` d'au moins 3:1 ou d'un second indice non coloré (barre latérale 2 px `{colors.primary}`, gras, coche). Définir `accent` = teinte propre ou imposer un indicateur sans couleur pour : item actif des menus et de Command, ligne survolée/sélectionnée, onglet actif. »

**F-04 High. `plafond-bar` marker has no valid background in the cases that matter** (DESIGN.md Colors "marqueur 90 %", Components `plafond-bar`). The marker is drawn at 90 % of the track, i.e. over the Kyuri fill as soon as usage >= 90 % (the exact case it exists for): 2,03 light, 1,00 dark (yellow marker on yellow fill). Track background is not defined; "jamais sur Dawn" is violated if the bar sits in a Dawn card (2,80). *Suggested wording:* « Le marqueur est un trait vertical de 3 px bordé de 2 px `{colors.background}` (liseré), dépassant de 4 px au-dessus et en dessous de la piste ; fond de piste = `{colors.background}` ; mesurer le marqueur contre le liseré (>= 3:1). Au franchissement, le texte adjacent affiche icône + « seuil de 90 % atteint ». »

**F-05 High. Public contact form is unspecified, including spam control** (EXPERIENCE.md UJ-3 step 4 is the climax; Open items only lists "anti-spam" as an assumption; no component row, no state). Missing: fields, required marking, labels, `autocomplete` (name, email), inline errors + summary, sending / success / failure status (4.1.3), data kept on error, spam control. A CAPTCHA puzzle would violate 3.3.8 (2.2). *Suggested wording (Component Patterns, row `contact-form`):* « Champs : nom, e-mail, message, tous avec libellé visible, `aria-required`, `autocomplete="name"`/`"email"`. Erreurs : récapitulatif en tête (`role="alert"` ou focus, pas les deux) + erreur en ligne reliée par `aria-describedby`. Envoi : bouton désactivé seulement pendant l'envoi ; succès dans une région `role="status"` (« Message envoyé. »), saisie conservée en cas d'échec. Anti-spam sans test cognitif : champ piège masqué (`aria-hidden`, `tabindex=-1`), délai minimal de soumission, limitation de débit côté serveur ; aucun CAPTCHA à image, énigme ou calcul. Vouvoiement. »

**F-06 High. Task check/reorder focus rule is contradictory and incomplete** (EXPERIENCE.md Interaction Primitives "Réordonnancement": "le focus reste sur la case suivante"; Component Patterns `task-row`). (a) Moving focus to another control after the user toggled one is an unexpected context change and jumps the screen-reader cursor. (b) The checked row is reordered: if the node is re-mounted, focus is lost; if moved, the user loses place. (c) Last task: no "next" box; the "Bravo" block and its two buttons appear with no focus or announcement rule (UJ-1 climax). (d) The live message "Tâche terminée, 2 restantes" does not name the task, and uncheck ("Décocher possible") has no message. *Suggested wording:* « Cocher : le focus reste sur la case actionnée, qui suit sa ligne (même nœud DOM déplacé, `key` stable, pas de remontage). `role="status"` : « {titre} terminée, {n} restantes, déplacée en position {k} ». Décocher : « {titre} rouvrie, {n} restantes ». Dernière tâche : le bloc « Bravo » reçoit `role="status"`, le focus reste sur la case ; les deux boutons sont les arrêts de tabulation suivants. »

**F-07 High. Assistant panel semantics are undefined** (EXPERIENCE.md Component Patterns `assistant-panel`, Accessibility Floor: "région nommée"). Not stated: modal (shadcn Sheet = focus trap, background inert) or non-modal (UJ-2 needs the page visible while it is open)? Landmark (`aside` with `aria-label`) vs `dialog`? DOM position (after `main`, so tab order is reading order)? Whether focus is trapped, and Tab/Shift+Tab behaviour at the edges. Also "réponses annoncées en `aria-live`": announcing a streamed answer plus sources verbatim is noisy and repeats on each token. *Suggested wording:* « Le panneau est **non modal** : `<aside aria-label="Assistant">`, placé après `main` dans le DOM, pas de piège de focus, fond non inerte. Ouverture : focus sur le champ de saisie. Réponse : pendant la génération `role="status"` « Recherche dans tes notes… » ; à la fin un seul message « Réponse prête, 3 sources » ; le texte de la réponse n'est pas dans une région live, le focus ne bouge pas. Erreur ou > 15 s : `role="status"` + « Réessayer ». »

### Medium

**F-08 Medium. Esc has no precedence and may destroy input** (EXPERIENCE.md Interaction Primitives: "Fermer le panneau, la modale, quitter l'édition"). Panel open + note being edited + dialog open: which one closes? Does Esc in the editor or the assistant field discard an unsent question or unsaved note? *Suggested wording:* « Esc ferme d'abord le niveau le plus haut (menu, popover > modale > panneau > mode édition). Esc ne supprime jamais de saisie : brouillon conservé, ou confirmation si des modifications ne sont pas enregistrées. Retour du focus : à l'élément qui avait le focus avant l'ouverture, y compris quand l'ouverture vient du raccourci (le « déclencheur » n'est alors pas un bouton) ; s'il n'existe plus, au `h1` de la page. »

**F-09 Medium. Shortcut conflicts and discoverability** (Interaction Primitives). ⌘K is bound to browser search on some browsers (Firefox, Chrome on Windows/Linux as Ctrl+K), ⌘J / Ctrl+J opens Downloads in Chrome and Firefox on Windows/Linux (check the Mac browsers used before committing). Shortcuts are not listed anywhere, there is no equivalent visible control for search, and no `aria-keyshortcuts`. They are modifier combinations so 2.1.4 does not apply, but `preventDefault` overrides browser functions. *Suggested wording:* « Chaque raccourci a un bouton équivalent visible avec nom accessible (« Rechercher », « Assistant ») et `aria-keyshortcuts`. Le raccourci ne s'active pas pendant une composition IME. Liste des raccourcis dans le menu d'aide. Valider ⌘K et ⌘J sur Safari, Chrome et Firefox Mac ; sinon proposer ⌘/ ou ⌥⌘J. »

**F-10 Medium. `data-table`: sort, row activation, naming** (Component Patterns `data-table`: "Tri, filtre… ligne cliquable et activable au clavier ; en-têtes `scope`"). Missing: `aria-sort` on the sorted `th` (one only), sort control as a `button` inside `th` with its name; non-sortable columns; announce result count after filter/search (`role="status"`: « 12 clients sur 40 »); accessible name (`caption` or `aria-label`). "Ligne cliquable et activable au clavier" invites `tr onClick` + `tabindex` + `role=button`, which breaks table semantics and nests interactive content. *Suggested wording:* « `<table>` natif avec `<caption>` (masquée visuellement). `th scope="col"` ; colonne triable = `<button>` dans le `th` avec `aria-sort="ascending|descending"` sur le `th` actif ; focus et ordre conservés après tri. Ligne cliquable : le lien (nom du client) est dans la 1re cellule, étendu à la ligne par CSS ; pas de `role` sur `tr`. Après filtre : `role="status"` annonçant le nombre de résultats. »

**F-11 Medium. Gauge text alternative is under-specified** (Component Patterns `plafond-bar`: "rôle `meter`/`progressbar`… texte alternatif du marqueur"). (a) Two roles are listed: choose one (`meter`, value is a measure, not task progress). (b) `aria-valuenow` alone gives a bare number: no `aria-valuemin/max`, no `aria-valuetext`, no accessible name. (c) A marker cannot carry its own alt text announced in context. (d) In the "paramètre manquant" state a meter must not be rendered (0 would be a false value). (e) Updates after an Encaissement (UJ-5) have no announcement. *Suggested wording:* « `role="meter"`, `aria-label="Plafond de chiffre d'affaires (estimation)"`, `aria-valuemin=0`, `aria-valuemax={plafond}`, `aria-valuenow={cumul}`, `aria-valuetext="{cumul} € sur {plafond} €, soit {p} % ; seuil de 90 % : {seuil} €"`. Marqueur `aria-hidden` (info portée par valuetext et le texte adjacent). Paramètre absent : aucun `meter`, seulement le message d'état. Mise à jour sur la même page : `role="status"` « Plafond mis à jour : {p} % (estimation) ». »

**F-12 Medium. No auth specification for accessible authentication (2.2, 3.3.8)** (Information Architecture row Connexion; scène B only describes the decorative panel). Missing: paste allowed in password fields, `autocomplete="username|current-password|new-password"`, show/hide password button with state, no puzzle/CAPTCHA, reset flow without cognitive test, error wording that names the field, session-expiry behaviour (2.2.1, note draft kept). *Suggested wording (Accessibility Floor):* « Connexion : e-mail + mot de passe avec `autocomplete` adaptés, collage autorisé, gestionnaires de mots de passe supportés, bouton « Afficher le mot de passe » (`aria-pressed`) ; aucune énigme, aucun CAPTCHA. Expiration de session : brouillon de Note conservé localement, message `role="alert"`. »

**F-13 Medium. Headings, page titles and route-change focus missing** (Accessibility Floor only lists landmarks and skip link). Not stated: one `h1` per page (is it the `gradient-banner` title on Cockpit, `{typography.display}` on the portfolio?), `h2/h3` order inside the Cockpit, assistant panel heading level, unique `<title>` per route (2.4.2), where focus lands after a Next.js client-side navigation, skip-link target (`main` needs `tabindex="-1"`), a skip link on the public page. *Suggested wording:* « Un seul `h1` par page = titre de page (`{typography.display}`), sections en `h2`, sans saut de niveau ; le niveau est sémantique, indépendant de la taille. `<title>` = « {Page} · LogMerry ». À chaque navigation, le focus va au `h1` (`tabindex="-1"`) et le titre est annoncé. Lien « Aller au contenu » en premier arrêt sur toutes les pages, cible `#main` focalisable. »

**F-14 Medium. Target size and checkbox hit area (2.5.8, 2.2)** (Accessibility Floor: only "sources… au moins 24 px"). shadcn Checkbox is 16 px; icon-only sidebar items, sort buttons, `citation-chip` (13 px label), copy/open buttons, "Plus de champs" are not covered. *Suggested wording:* « Toute cible interactive >= 24 × 24 px (hors texte courant), recommandée 32 px sur desktop ; la case à cocher de `task-row` a une zone cliquable d'au moins 24 px (`::after` étendu), sans chevauchement avec le lien du titre. »

**F-15 Medium. "Focus not obscured" asserted without a mechanism (2.4.11, 2.2)** (Interaction Primitives: "jamais masqué par la barre latérale ou le panneau"). Layout does not say whether the panel pushes content (reflow) or overlays it (≥ 1024 px, Responsive), nor how sticky elements (banner, toasts) behave. *Suggested wording:* « Le panneau assistant réduit la largeur de `main` (colonne de grille), il ne le recouvre pas ; `scroll-padding` égal à la hauteur des éléments sticky ; les toasts n'apparaissent pas sur la zone de focus (coin bas gauche, hors panneau) et sont fermables au clavier. »

**F-16 Medium. Reflow and zoom not covered (1.4.4, 1.4.10)** (Responsive & Platform: ≥ 1024, tablette "non décrit", téléphone "consultation"). A desktop user at 400 % zoom sees a 320-CSS-px viewport: sidebar, `data-table`, panel and forms must reflow; tables are not specified for the phone. Type sizes are in px. *Suggested wording:* « Tout le contenu reste utilisable sans défilement bidirectionnel à 320 px (hors tableaux, qui défilent horizontalement dans un conteneur focalisable `tabindex=0` nommé) ; panneau assistant en pleine largeur sous 1024 px ; tailles de police en `rem`. »

**F-17 Medium. Forms: error wiring and field details incomplete** (Component Patterns Formulaires, Accessibility Floor). Present: labels, inline error, summary. Missing: `aria-invalid` + `aria-describedby`; required marking not by colour/asterisk alone ("obligatoire" in the label or legend); errors announced after submit (focus on summary, not also `role=alert`); summary links move focus to the field; `autocomplete` on identity fields (1.3.5); "Plus de champs" needs `aria-expanded`/`aria-controls`; date fields (Étape, Devis, Échéance, date de vérification) have no keyboard entry rule; amounts have no format rule; no redundant-entry rule (3.3.7) beyond prospect→client (e.g., default the "date de vérification" to today). *Suggested wording:* « Date : saisie texte JJ/MM/AAAA avec sélecteur optionnel (`Calendar` navigable aux flèches), format indiqué dans le libellé. Montant : `inputmode="decimal"`, virgule acceptée. Champs requis : « (obligatoire) » dans le libellé + `aria-required`. Toute information déjà saisie dans le parcours (client, mission) est préremplie, jamais redemandée. »

**F-18 Medium. Sidebar and navigation semantics** (IA, Responsive). Missing: current page (`aria-current="page"` plus a non-colour cue, see F-03), icon-only collapsed state needs accessible names (tooltips are not names; tooltip must meet 1.4.13: hoverable, dismissible, persistent), collapse button `aria-expanded`, state persisted, phone `Sheet` focus management (focus to first link, return on close). *Suggested wording:* « Éléments de la barre latérale : texte visible ou `aria-label` quand repliée ; `aria-current="page"` + barre de 3 px `{colors.primary}` ; bouton de repli `aria-expanded` ; infobulle sur focus et survol, fermable par Esc. »

**F-19 Medium. Public portfolio: alt text and Réalisation fields** (UJ-3 step 3: "captures d'écran"; Open items: fields undefined). No alt-text requirement, no rule for the "chiffre de résultat", no image dimension/reflow rule. *Suggested wording:* « Chaque capture publiée exige un texte alternatif saisi dans l'éditeur de Réalisation (bloquant à la publication), 1 phrase décrivant ce que la capture montre ; capture purement décorative marquée `alt=""` explicitement. Le chiffre de résultat est du texte, pas une image. »

**F-20 Medium. Warning icon contrast contradicts the stated floor** (DESIGN.md `warning-icon` #E45C10; Colors "Plus bas ratio… non-texte 3,28 / 5,06"). Tobiko icon on Dawn card is 2,80 (light) and on card-dark 3,03 (dark), both below or at the floor and not in the declared minima. Because the text duplicates the meaning it is borderline, but the document claims 3:1 everywhere. *Suggested wording:* « `warning-icon` : Tobiko uniquement sur `{colors.background}` (3,28) ; sur `{colors.card}` utiliser `{colors.warning}`. Corriger « plus bas non-texte » (sombre) à 3,03 ou retirer Tobiko du sombre. »

**F-21 Medium. Dark scene C (cockpit banner) is undecided but the Do's forbid unpaired themes** (DESIGN.md gradient-banner = gradient-2 + Forest only; Open items "en sombre non décidé"). In dark mode a Dawn→Sneezeweeds banner with Forest text sits on a Forest page: either a bright block in dark mode or an undefined state, and `gradient-banner` uses `{colors.forest}` that is the page background in dark. *Suggested wording:* « Sombre : `gradient-banner` = `gradient-5` + texte `{colors.chalk}` (6,65 au pire) ; ou aplat `{colors.card-dark}` sans dégradé. Décider avant la passation. »

**F-22 Medium. Citations are not associated with bullets for assistive tech** (Component Patterns `assistant-panel`: bullets then sources below). A screen-reader user hears bullets, then an unattached list of chips. FR-4 requires a valid citation per bullet. *Suggested wording:* « Chaque puce porte un repère numéroté « [1] » (lien vers la source correspondante, nom « Source 1 : {titre de la note} ») ; les sources forment une `<ol>` nommée « Sources » ; `citation-chip` = lien (navigation) ou bouton (copie), jamais un `div` cliquable. Les puces sont de vrais `<ul><li>`. »

**F-23 Medium. Links and non-colour distinction** (DESIGN.md: link style absent; `muted-foreground` and `foreground` differ only by hue/lightness). Inline links in notes, summaries, "Paramètres sources" are undefined. 1.4.1: link vs surrounding text needs 3:1 or underline. *Suggested wording:* « Liens dans le texte : soulignés en permanence, couleur `{colors.primary}` (clair) / `{colors.primary-dark}` (sombre) ; soulignement conservé au survol et au focus. »

### Low

**F-24 Low. Reduced motion covers only reorder and panel** (Interaction Primitives). Not covered: satisfaction feedback on check, `Skeleton` pulse, "Recherche dans tes notes…" spinner (2.2.2 if > 5 s), toasts, smooth scrolling. *Suggested wording:* « `@media (prefers-reduced-motion: reduce)` : aucune animation hormis changement d'état instantané ; retour de satisfaction = coche + titre barré, sans mouvement ; indicateur d'attente en texte statique. »

**F-25 Low. Toasts and confirmations** (shadcn Toast default; « Copier le texte » confirmation). Duration, persistence for toasts with actions, `role="status"`, pause on hover/focus, keyboard dismissal not stated (2.2.1). *Suggested wording:* « Toast informatif : `role="status"`, 6 s minimum, mis en pause au survol et au focus ; toast avec action : persistant jusqu'à fermeture. »

**F-26 Low. Citation click behaviour and « Ouvrir »** (`citation-chip`: "ouvre la Note source à l'Extrait"). Focus target and non-colour highlight of the excerpt are undefined; the assistant keeps the conversation across pages (does focus move to the note heading? does the panel stay?). *Suggested wording:* « Ouverture d'une citation : navigation dans le même onglet, focus sur l'Extrait (`tabindex=-1`), surligné avec fond + contour (pas la couleur seule) ; le panneau reste ouvert. Même onglet, sauf mention « (nouvel onglet) » dans le nom accessible. »

**F-27 Low. Rich-text note editor semantics unspecified** (IA row Notes; Esc "quitter l'édition"). Editor library roles, toolbar keyboard access (roving tabindex), Tab behaviour (does Tab exit the editor or indent?), generated summary announcement (« résumé généré » + completion status) missing. *Suggested wording:* « Éditeur : `role="textbox"` multiligne nommé, barre d'outils en `role="toolbar"` à tabindex itinérant, Tab sort de l'éditeur (pas de piège), Esc ne le quitte que s'il n'y a pas de menu ouvert ; fin de génération du résumé : `role="status"`. »

**F-28 Low. States without non-colour or hover/disabled/placeholder specs** (DESIGN.md frontmatter has no tokens for placeholder, disabled, hover, selected). Placeholder text must reach 4,5:1 (default shadcn `text-muted-foreground`, here 5,68 OK on Dawn but not stated for inputs on Chalk/card); disabled is exempt but must remain legible. *Suggested wording:* « Placeholder = `{colors.muted-foreground}` (>= 4,5:1), jamais seul comme libellé. Désactivé : opacité 50 % + `aria-disabled` ; jamais le seul moyen d'indiquer un état. »

**F-29 Low. Forced-colors / Windows High Contrast not addressed**. Marker, fill, checkbox tick and focus ring depend on `background-color`, which forced-colors mode removes. *Suggested wording:* « En `forced-colors: active`, la jauge, le marqueur et la case cochée utilisent `Highlight`/`CanvasText` via `border` ou `outline`, pas seulement `background`. »

## Checked and with no gap
Dragging alternative (2.5.7): no drag, stated. Status not by colour alone: stated in Do's and Component Patterns. Gradient text pairs: validated, decorative gradients `aria-hidden`, no text on 03/04. Skip link, landmarks, error summary with focus, labels, 24 px for sources: present (completeness in F-13, F-14, F-17).
